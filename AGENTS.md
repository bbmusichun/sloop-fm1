# Working in this repository (Base44 sandbox)

Snoop37 / SLOOP is a hardware firmware project (C for the JieLi AC791N chip, built
with the JieLi toolchain and the AC79 SDK — see `BUILDING.md`). Neither the toolchain
nor the SDK is part of the repository, so the firmware is **not** built in the sandbox.

## What runs in the preview

The project's static web app: `docs/` is the GitHub Pages root and is served as-is.

```
docker compose -f docker-compose.base44.yml up -d      # web: python:3.12-slim, static server on :3000
```

- `/` → redirects to `/webapp/installer/`
- `/webapp/installer/` → firmware installer (Web USB/Serial; needs the real keyboard or a `.fwsc` file)
- `/webapp/editor/` → SLOOP editor. Without hardware add **`?mock=1`** to use its built-in simulated
  device (the editor ships a mock; `&legacy=1` simulates an older firmware). Web MIDI itself is a
  browser permission and there is no keyboard in the sandbox, so only the mock path is verifiable here.
- `/webapp/editor/sloop-editor.html` → the editor as one offline file

Nothing is compiled for the site and the server sends `Cache-Control: no-store`, so edits
show up on reload. The static server is `.base44/serve_site.py`, and it serves the editor
from its **source**, not from the generated copy: `/webapp/editor/` and
`/webapp/editor/index.html` come from `web/editor.html`, plus `preview.js`,
`preview-worklet.js`, `fukiai.ttf` and `FUKIAI-LICENSE.txt` from `web/`. (The copy in
`docs/webapp/editor/` is an older build — it predates the SMK-37 DAW tab and
`STOCK_RELEASE` — so edit `web/editor.html`, never that copy.) Files the source does not
hold still come from `docs/`: `sloop-preview.wasm`, `sloop-editor.html`, the installer.

## Regenerating the site

`docs/` is generated by `web/make_site.py`, which needs a built package
(`build/*.fwsc`) and therefore the firmware toolchain. The editable sources of the
pages are `web/editor.html` (editor), `web/index_pkg.html` + `fm1pkg.js` + `fm1ota.js`
(installer) and `web/make_site.py`. The editor is served from source (above). The
**installer is not**: `/webapp/installer/` is the generated `docs/webapp/installer/index.html`,
because its page needs `fm1pkg.js` + `fm1ota.js` inlined and a package's version, identity
and SHA-256 spliced in. To refresh it: `python3 web/make_site.py <pkg>.fwsc <version> docs`
(needs a `.fwsc`; `docs/firmware/sloop-2.7.1.fwsc` is an identity `FM-1_900` package and
works as input).

## Checks that do work here

- Web page JS tests (no browser, no hardware — they cover the editor's mock device, the
  package and update protocols of the installer) run in a Node container at the repo root:
  `docker run --rm -v "$PWD":/app -w /app node:22 node web/test_web.mjs`
  (the package-format cases are skipped without a `build/`). The `web` service image is
  Python only, so it has no `node`.
- `tests/run_tests.sh` (host C tests) needs `./build.sh` output and `AC79_SDK`; it cannot run here.

## Notes for working in the preview

- `docs/index.html` is a meta-refresh redirect to `/webapp/installer/`, and the installer and
  editor are separate HTML documents (not one SPA), so open them by URL
  (`/webapp/editor/?mock=1`), not by in-page routing.
- The editor needs a click on **connect** even with `?mock=1` before its panels fill in.
- Web MIDI / Web Serial need the real keyboard, so installing firmware cannot be exercised here.
